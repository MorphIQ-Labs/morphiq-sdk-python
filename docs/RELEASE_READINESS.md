### Timing limits

the README fixture request took 0.15 s and 0.20 s respectively. Optional extras
plus test tooling installed in 17.97 s and 19.04 s. The locally built Docker image

These are observations on an existing macOS ARM development machine with warm
package/image caches. They exclude fresh-account signup, public package/image
pulls and production API execution. **They do not demonstrate the five-minute
first-use target or clean-machine Docker onboarding.**

## Reproduce candidate acceptance

Use the exact reviewed candidate checkout and a controlled service built from
`contracts/provenance.json`. Start the service in loopback open admission mode,
then build the sdist and wheel without changing release versions:

```sh
python -m build --outdir /tmp/sdk-candidate-dist /path/to/candidate-checkout
python scripts/check_release_candidate.py \
  --wheel /tmp/sdk-candidate-dist/morphiq_sdk-0.1.0-py3-none-any.whl \
  --source /path/to/candidate-checkout \
  --python /path/to/python3.11 \
  --api-url http://127.0.0.1:19871 \
  --report /tmp/sdk-candidate-311.json
```

Repeat with the other supported CI interpreter. The runner verifies the served
contract digest before testing, rejects non-loopback API URLs, creates disposable
virtual environments, strips API credentials/source-import environment settings,
checks the README against a local fixture, installs optional extras, registers an
isolated kernel and runs candidate tests without copying `src/`. It writes a JSON
summary and sibling log. It does not read `.env`, publish artifacts or run a
production numerical request. Inspect the test summary for unexpected skips.

For the notebook image, build from the same candidate and run
`python scripts/check_notebook_container.py --image <candidate-image>`.
Keep local build/readiness timings separate from public pull and evaluator times.

## Adoption measurement proposal

Use an opt-in evaluator checklist: candidate/source/image identity, supported
platform, elapsed install/signup/key/first-result stages, first useful result,
request ID, reported CU or unknown-charge status, batch item success/failure counts
and categorized setup/API errors. Do not record API keys, request payloads,
portfolio identifiers or private prices. No SDK telemetry is enabled or added.
Choose retention/access and any website/account analytics with their owners before
collection; use existing server records for charge reconciliation.
